# Demo v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the hosted demo as a full-fidelity South African simulation: a complete fictional persona, roughly 20 employers across seven sectors and nine province labels, seeded documents and answers, and a simulated portal with real form controls that fills, reviews and submits a packet v2 without touching the real vault, a key or the network.

**Architecture:** Split the demo fixtures into `persona.js` (person, profile v2, answers, memory, sample documents, question library), `jobs.js` (employers, jobs, hunter rows, feeds, tailored text) and `fixtures.js` (seed assembly). Seed sample documents into the demo's own `sessionStorage` vault. Render the persona's documents read-only in Settings. Build the simulated portal on `buildApplyPacketV2`, let the visitor edit real form controls, revalidate the edited packet with `sanitisePacketV2` in `simulationApi.js`, and record the result as `web-guided` / `copilot-confirmed`. Extend the isolation proof to a sentinel document in the real IndexedDB documents store.

**Tech Stack:** React 18, Vite 7, `@sajas/core` packet v2, Node 24 `node:test`, Playwright 1.63 (Chromium), npm workspaces.

**Spec:** [`docs/superpowers/specs/2026-11-01-automation-and-data-depth-design.md`](../specs/2026-11-01-automation-and-data-depth-design.md), section "Demo v3".

## Global Constraints

- No server, no accounts, no analytics. The hosted app remains static.
- BYOK only. Demo mode never reads, holds, validates or requests an Anthropic key.
- Demo data lives only in `sessionStorage` under `sajas:demo:` or an in-memory adapter. Demo code never reads or writes IndexedDB `sajas-web`, including its `documents` store.
- Demo code never calls `fetch` outside the intercepted API base. UI files only, and every call must name `API_BASE`.
- Every demo host and email uses a reserved `.test` domain. Every employer and person is fictional.
- All automated tests are offline. Never run `npm run smoke:live`, `node evals/run.mjs --live`, or anything that needs `ANTHROPIC_API_KEY`. Never set a key.
- Key-shaped strings must be assembled at runtime, never committed as literals.
- Never bypass the pre-commit hook. `--no-verify` is forbidden.
- Run npm commands from `sa-job-agent-suite/`. Run `node tools/check-secrets.mjs --all` from the worktree root.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Do not touch the desktop app, `SYNTHETIC_DEMO`, `server/src/demo.js` or the desktop copilot.
- No em dashes in new copy. Light mode. Restrained screens; the landing page keeps its distinctive treatment.
- Production deploys need explicit approval. Assistant-opened PRs are pre-authorized for merge.
- Every task follows TDD: failing test, run it, minimal implementation, run it, commit.

const IDENTITY_KEYS = new Set([
  'fullName', 'firstName', 'lastName', 'preferredName', 'email', 'phone',
  'linkedInUrl', 'portfolioUrl', 'githubUrl', 'city', 'province', 'postalCode',
  'country', 'currentCompany', 'currentTitle', 'yearsExperience', 'highestQualification'

export function portalSections(fields = []) {
  const identity = fields.filter((field) => IDENTITY_KEYS.has(field.key));
  const employer = fields.filter((field) => field.source === 'answer-bank');
  const eligibility = fields.filter(
    (field) => !IDENTITY_KEYS.has(field.key) && field.source !== 'answer-bank'
  );
  return [
    { id: 'identity', title: 'Your details', fields: identity },
    { id: 'eligibility', title: 'Eligibility and availability', fields: eligibility },
    { id: 'employer', title: "This employer's questions", fields: employer }
  ].filter((section) => section.fields.length);
}

export function withEdits(fields = [], edits = {}) {
  return fields.map((field) => (
    Object.prototype.hasOwnProperty.call(edits, field.key)
      ? { ...field, value: String(edits[field.key] ?? '').trim() }
      : field
  ));
}

export function submissionFields(fields = []) {
  return fields
    .filter((field) => field.label && field.value)
    .map(({ label, value }) => ({ label, value }));
}

export function summariseSubmission(
  packet,
  { delivery, submittedBy = 'user', fields = null, documents = null, confirmation = null } = {}
) {
  if (!SUBMISSION_DELIVERIES.includes(delivery)) {
    throw new TypeError(`Unknown application delivery: ${delivery}`);
  }
  if (!SUBMISSION_SUBMITTERS.includes(submittedBy)) {
    throw new TypeError(`Unknown application submitter: ${submittedBy}`);
  }
  const source = documents ?? packet?.documents ?? [];
  const available = source.filter((doc) => doc.available);
  const sourceFields = fields || [
    ...(packet?.identity || []),
    ...(packet?.questions || [])
  ].map(({ label, value }) => ({ label, value }));
  const clean = cleanSubmission({ documents: available, fields: sourceFields, confirmation });
  return {
    delivery,
    submittedBy,
    site: packet?.job?.site || '',
    ...clean
  };
}
